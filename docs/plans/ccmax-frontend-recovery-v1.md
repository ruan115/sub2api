## 3. 后续源码结构（计划，不预建空目录）

旧线上为 React；当前 CCMAX 为 Go embed 的原生 `web/index.html + app.js + styles.css`；Sub2API 的 `frontend/` 才是 Vue。三者不可混称或直接相互覆盖。

拟在 CCMAX 内建立一个明确归属的 React/TypeScript 源工程，不再扩展 Portunex 演示工程：

```text
ccmax-manager/ui/
  src/app/                             # 入口、路由、会话适配、页面框架
  src/design-system/                   # 有来源的颜色/字体/间距/基础组件
  src/modules/
    overview/                          # 账号与运行概览
    accounts/                          # 账号池、上号、状态、配额展示
    proxies/                           # 代理池、绑定、连通状态
    scheduling/                        # 分组与调度策略
    execution/                         # slot、模式、节点、drain、重建
    diagnostics/                       # 错误、授权与操作审计
  src/adapters/ccmax/                   # 既有 API 到 UI model 的显式映射
  src/fixtures/                        # 合成数据；不能包含线上账号
  tests/                               # 跨页面测试；单元测试就近
  dist/                                # 忽略的预览构建物，不自动覆盖 ../web/
```

只创建实际切片所需模块。页面不得直接访问数据库、Docker、Vault 或生产地址；凭据不得作为演示数据。生产入口与 `go:embed` 切换必须是后续独立、可回滚的变更。

## 4. 原外观与 CCMAX 功能的对应

| 线上视觉来源 | CCMAX 目标 | 不允许默认等同 |
| --- | --- | --- |
| dashboard 框架、主题、导航、统计卡片 | CCMAX 总览与模块外壳 | 旧金额、角色和统计口径不能直接复用 |
| Provider 页面、筛选、表格与详情面板 | Claude 账号池、账号详情 | Provider ID 不是 CCMAX account ID；导入/授权动作需适配 |
| 日志、追踪页面与时间筛选器 | 错误、授权和操作诊断 | 日志字段、权限与脱敏要求并不相同 |
| 颜色、字号、留白、边框、图标、动效 | 公共设计系统 | 静态 class 存在不等于页面已视觉验收 |
| 原站中没有对应页面的执行槽位功能 | CCMAX 执行环境管理 | 必须标明新增设计，不能声称“旧版原样恢复” |

不要借恢复配色再次引入 Portunex 用户、订单、支付、OIDC 或账本模块。原站首页营销动画不是 CCMAX 账号维护主线，保全可做，首批重建不优先做。

## 5. 阶段与验收

- **U0 原件保全**：准确资源清单、远端/本地 hash 一致、私有权限、隔离分类、独立完整性复核。结论只能是“取回了哪些发布资源”。
- **U1 视觉基线**：从已审阅 CSS、组件和布局建立来源锚点；整理桌面/移动端、明暗主题和关键交互截图。若要执行原 JS，必须先完成静态审核和禁止外联/真实凭据的隔离方案，不能直接在带登录态浏览器运行。截图不足时明确差异，不猜称像素级一致。
- **U2 可维护 UI**：先做总览、账号列表与详情三个界面，使用合成数据，按旧外观重建 TSX。类型检查、组件交互、响应式、键盘导航与截图对照通过后才扩展。
- **U3 CCMAX 只读适配**：对接已有安全边界下的总览、账号与代理查询；验证分页、筛选、错误、权限、空态及隐藏敏感字段。不得通过禁用鉴权“跑通”。
- **U4 管理写操作与执行页**：逐项接入既有上号、绑定、调度、归档和执行设置；写入确认、幂等、权限回归与后台状态一致，缺失 API 单独列入执行面计划。
- **U5 切换**：独立 review、本地 E2E、明确构建入口/回滚方案，用户另行批准后才可部署；本次不部署。
